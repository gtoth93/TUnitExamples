TUnit
    new testing framework for .net, built on Microsoft.Testing.Platform
    tries to take the strengths of previous testing frameworks
    Intro
        install
            template: dotnet new install TUnit.Templates
                    dotnet new TUnit --name "YourProjectName"

            manual: dotnet new console --name "YoutProjectName"
                    cd YourProjectName
                    dotnet add package TUnit
                    delete program.cs

            some global usings are automatically added, like test attributes and assertions
            built in extensions: Microsoft.Testing.Extensions.CodeCoverage (coverlet is not compatible), Microsoft.Testing.Extensions.TrxReport
            warning: do not use Microsoft.NET.Test.Sdk
        write test
            create class
            create method with [Test]
                method can be sync (void), or async (async Task)
                TUnit assertions have to be awaited, in that case all tests will be async
        run test
            command line
                for single projects: dotnet run --report-trx --coverage
                for the entire solution: dotnet test --report-trx --coverage (requires global.json configured for mtp)
    Writing tests
        Things to know
            tests run in parallel by default (can be controlled)
            all tests have separate test class instances
            to share data between tests, use static props/fields, or ClassDataSource

        Test Data
            Arguments - for fixed inline values
                Extra parameters
                    DisplayName - adds human readable name for test cases, can use parameter substitution $paramName, or positional $arg1, $arg2...
                    Categories - for filtering
                    Skip - skips specific test, with reason
            MethodDataSource - for data from a method
                if there are too many Arguments, data is more complex, or just not constant (reference types)
                first and second parameter is type and method name
                or with generics, type parameter is the class, first parameter is the method name in that class
                for value types: you can return T
                for reference types: return a Func<T> where the Func returns a new T()
                for multiple test cases: return IEnumerable<Func<T>>
                for aot compatibility: use static
                for async: IAsyncEnumerable<Func<T>>
                if you need instance members in the data source: InstanceMethodDataSource
            ClassDataSource - shared object with lifecycle
                Nested data sources
            TestDataRow - Reusable data row
            MatrixDataSource - combinations of multiple parameters
            CombinedDataSources - combination of multiple data sources
